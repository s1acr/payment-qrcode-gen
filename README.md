# 收款码合并工具

将**支付宝收款码**和**微信收款码**合并成一张通用收款二维码:顾客用支付宝扫就进支付宝付款页,用微信扫就进微信付款页。

| 特性 | 说明 |
|---|---|
| 纯静态零后端 | 无服务器、无数据库,整个目录部署到任意静态托管即可 |
| 隐私优先 | 收款码解码、合并、美化全部在浏览器本地完成,收款链接不上传 |
| 自动分流 | 中转页按扫码环境分流:支付宝直跳、微信直跳或长按识别 |
| 码面美化 | 前景颜色、中心 Logo、底部文字,一键下载 PNG 打印 |
| 本地历史 | localStorage 本机保存,可随时重新生成、复制链接、删除 |

## 工作原理

```
上传两张收款码 → 浏览器本地解码出支付链接
       ↓
生成合并二维码,内容为:
https://<你的域名>/pay.html#a=<支付宝链接>&w=<微信链接>
       ↓
顾客扫码打开 pay.html,页面按 User-Agent 分流:
  · 支付宝(AlipayClient)      → 跳转到支付宝收款链接
  · 微信(MicroMessenger)
      - https://wx.tenpay.com/…、https://payapp.wechatpay.cn/… → 直接跳转微信收款页
      - wxp://f2f…              → 页面内渲染二维码,提示「长按识别」
  · 其他浏览器                   → 提示用支付宝/微信扫码,可复制链接
```

两个支付链接直接编码在合并二维码内,因此不需要任何服务端存储。**合并码编码的是生成时的站点域名**,换域名部署后需用历史记录重新生成。

## 快速开始(本地运行)

> 直接双击 `index.html`(file:// 协议)无法生成有效合并码,必须通过 HTTP 访问。

```bash
# 任选其一
npx http-server -p 8080
python -m http.server 8080
```

VS Code 用户也可直接用 Live Server 启动。浏览器打开 <http://localhost:8080> 即可在电脑上生成、下载。

> **本机地址陷阱**:合并码编码的是**生成时浏览器地址栏里的域名**。在 `localhost` / `127.0.0.1`(含 VS Code Live Server 默认的 `127.0.0.1:5500`)下生成的码,手机扫码会去访问手机自己,必然打不开。真机测试请用下面的局域网方式,或部署后使用;界面对本机地址也会给出警示。

### 真机扫码测试

用电脑的局域网 IP 访问(如 `http://192.168.1.10:8080`),生成的合并码会编码该地址,同一 Wi-Fi 下的手机可直接扫码实测。**支付宝、微信各扫一次均正常跳转,才算可用**。

## 部署上线

把整个目录部署到任意静态托管:

| 平台 | 方式 |
|---|---|
| GitHub Pages | 推送仓库 → Settings → Pages 选择分支根目录 |
| Cloudflare Pages | 连接仓库或直接拖拽上传目录 |
| Vercel / Netlify | 导入仓库,无需构建命令 |
| 自有服务器 | Nginx 指向本目录即可 |

页面已内置 title / description / Open Graph / JSON-LD 结构化数据与 `robots.txt`,静态托管部署后无需额外 SEO 配置。

**部署后必须用手机真机分别用支付宝、微信扫一次合并码实测**,确认跳转正常。

## 使用步骤

1. 打开支付宝 →「收钱」→ 保存收款码图片;打开微信 →「收付款」→「二维码收款」→ 保存收款码图片
2. 在本站分别上传两张图片(识别失败时可展开「手动粘贴收款链接」)
3. 选择美化选项(前景颜色 / 中心 Logo / 底部文字),点击「生成合并收款码」
4. 下载 PNG,打印或保存到手机;**打印推荐经典黑前景**,尺寸不小于 5×5cm
5. 历史记录自动保存在浏览器 localStorage,可随时重新生成下载、复制链接或删除

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机扫码无反应、打不开页面 | 在 `localhost` / `127.0.0.1` 下生成,码指向本机 | 改用局域网 IP 或部署后的域名重新生成 |
| 上传后识别失败 | 图片模糊、被裁剪或不是收款码 | 重新保存原图,或展开「手动粘贴收款链接」 |
| 微信扫码提示「长按识别二维码」 | 微信个人码为 `wxp://` 格式,网页无法直接拉起支付 | 设计如此,引导顾客长按识别即可 |
| 彩色码偶尔扫不出 | 彩色前景与白底对比度不足 | 输出时已自动映射为同色相深色变体;打印仍推荐经典黑 |
| 原本能扫的码突然扫不出 | 更换了部署域名,旧码仍指向旧域名 | 用历史记录中的链接重新生成下载 |
| 微信提示「即将访问外部网页」 | 陌生域名的正常安全提示 | 点「继续访问」;域名被微信屏蔽时更换域名 |

## 已知限制

- **wxp:// 格式的微信个人收款码**无法通过网页跳转直接拉起支付,合并码方案是展示二维码让付款者「长按识别」,多一步操作;`https://wx.tenpay.com/…`、`https://payapp.wechatpay.cn/…` 格式则可直接跳转。
- 合并码内容包含两个完整链接,微信链接较长时二维码更密集,打印尺寸建议不小于 5×5cm,并务必实测。
- 部署域名需要能被大陆手机正常访问(GitHub Pages 在部分地区不稳定,推荐 Cloudflare Pages 或国内静态托管;绑定国内服务器域名需备案)。
- 历史记录的域名与当前访问域名不一致时,界面会给出提示。

```
└── devtest/roundtrip.js
```
